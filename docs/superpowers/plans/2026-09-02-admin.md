# Admin (espace d'édition) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected `/admin` on the site where the artist edits texts, sculptures, and videos; each save commits to GitHub and Vercel republishes.

**Architecture:** Static Astro site plus on-demand `/admin/*` routes via `@astrojs/vercel`. Pure modules in `src/admin/` (auth, github, content, uploads) are unit-tested; Astro pages are thin: parse form → validate (zod) → call module → redirect with a flash message.

**Tech Stack:** Astro 7, `@astrojs/vercel`, `yaml`, `sharp` (already present), node `crypto`, zod (`astro/zod`), Vitest.

**Spec:** `docs/superpowers/specs/2026-09-02-admin-design.md`

## Global Constraints

- French UI. Same palette/fonts as the site (`global.css`), plain forms, no client JS required.
- Secrets only from env: `GITHUB_TOKEN`, `GITHUB_REPO`, `GITHUB_BRANCH`, `SESSION_SECRET`. Never commit `.env`.
- Slugs `^[a-z0-9-]+$`. Validate every form with zod. Sniff uploads by magic bytes.
- Local testing writes to branch `admin-test`, never `master`.
- Commit after each task with the session trailer.
